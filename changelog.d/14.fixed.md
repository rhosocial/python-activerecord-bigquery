Correct the partition state answer shape after core made `TableState.partitioning` non-optional (`1f177724`). `get_partition_state()` (sync and async) now returns a `PartitionState` for every table: an unpartitioned table answers the empty state whose `scheme` is `None`, never a `None` object, while the catalog's single `partition_id = NULL` row still means "no partitions" rather than a bound. `parse_partition_state()` and `parse_table_state()` follow the same contract, so `TableState.partitioning` is always a `PartitionState`, and the CLI's defensive `None` fallback is gone. Tests, the family guard and the English/Chinese introspection docs now pin the empty-state answer.
