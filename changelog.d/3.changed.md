Refuse the BigQuery clauses its grammar cannot express by name instead of dropping them silently or emitting SQL the server rejects: `INTERSECT ALL` and `EXCEPT ALL` previously produced invalid SQL, identity options outside GoogleSQL's `identity_column` grammar (`MINVALUE`/`MAXVALUE`, `CYCLE`/`NO CYCLE`, `ORDER`/`NO ORDER`, `CACHE`/`NO CACHE`) were dropped or reported under the wrong option name, an explicit `CREATE MATERIALIZED VIEW ... WITH [NO] DATA` was silently ignored, `DROP MATERIALIZED VIEW ... RESTRICT` was ignored, and transaction `WAIT`/`NO WAIT` were dropped. Each now raises `UnsupportedFeatureError` naming the exact request. The 43 expression classes this dialect implements no formatter for now report `UnsupportedFeatureError` naming the missing statement instead of an `AttributeError`. In the other direction, `DROP SCHEMA ... CASCADE`, previously refused although the documented grammar carries it, and `DROP SCHEMA ... RESTRICT`, previously ignored, now render per the `DROP SCHEMA ... [CASCADE | RESTRICT]` grammar.
