`TRIM` now renders as BigQuery's own spelling through the new `BigQueryTrimMixin`, because BigQuery has no ANSI `TRIM(BOTH 'x' FROM y)` form at all: its `TRIM` takes the value and an optional character set and always removes from both ends, and the direction is carried by separate `LTRIM` / `RTRIM`, so the shared default renderer emitted syntax the server rejects rather than a differently spelled one. The mapping is `BOTH` → `TRIM(x[, chars])`, `LEADING` → `LTRIM(x[, chars])` and `TRAILING` → `RTRIM(x[, chars])`; the operands' parameters in order, the optional character set and the optional alias are the default's. `LPAD`, `RPAD` and `REPEAT` are the shared spellings verbatim and are composed unchanged from core's `LpadMixin` / `RpadMixin` / `RepeatMixin`. The round-trip matrix accounts for every formatter this dialect does not implement in a pinned `UNMODELLED_FORMATTERS` table, because core reports a missing formatter through the same `UnsupportedFeatureError` a capability probe uses and the type alone can no longer tell the two apart. `DateTimeColumn` is followed in its rename to `TimestampColumn`.
