Implement the rebuilt core's `ColumnTypeSupport` protocol: the new `BigQueryColumnTypeMixin` answers the eighteen-entry closed list of common Python types with a column class each, exposed as `BIGQUERY_COLUMN_TYPES`, and is composed into `BigQueryDialect` — the rebuilt core declares no generic common-type table to sit behind it, so this table is the answer the model layer reads. No entry answers `None`, because BigQuery has both a native `ARRAY<T>` and a documented `JSON` type and so has nothing the protocol's last resort exists for. `DATE_DIFF` now renders instead of raising, with the end date first as the server requires and a week spelled `DAY / 7` because BigQuery has no WEEK part, and `JSON_QUERY` / `JSON_VALUE` replace the core default's `JSON_EXTRACT` / `JSON_UNQUOTE`, which BigQuery does not have. Python 3.15 joins the supported range (3.10 through 3.15 inclusive), the CI matrix and the classifiers; the leg is GIL-only, because `google-cloud-bigquery` 3.46.1 is a universal wheel with a `Python :: 3.15` classifier but publishes no cp315t wheel.
