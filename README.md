## Quick Start

```python
from typing import ClassVar, Optional

from rhosocial.activerecord.base import FieldProxy
from rhosocial.activerecord.backend.impl.bigquery.backend import BigQueryBackend
from rhosocial.activerecord.backend.impl.bigquery.config import BigQueryConnectionConfig
from rhosocial.activerecord.backend.expression import CreateTableExpression
from rhosocial.activerecord.backend.expression.statements import ColumnDefinition
from rhosocial.activerecord.backend.expression.types import IntegerType, VarCharType
from rhosocial.activerecord.model import ActiveRecord


class User(ActiveRecord):
    __table_name__ = "users"

    id: Optional[int] = None
    name: str
    email: str

    c: ClassVar[FieldProxy] = FieldProxy()


User.configure(
    BigQueryConnectionConfig(
        project="my-gcp-project",
        dataset="my_dataset",
        credentials_path="/path/to/service-account.json",
        location="US",
    ),
    BigQueryBackend,
)

dialect = User.__backend__.dialect
User.__backend__.execute(*CreateTableExpression(
    dialect,
    "users",
    columns=[
        ColumnDefinition(dialect, "id", IntegerType(dialect)),
        ColumnDefinition(dialect, "name", VarCharType(dialect, 100)),
        ColumnDefinition(dialect, "email", VarCharType(dialect, 255)),
    ],
).to_sql())

user = User(name="Alice", email="alice@example.com")
user.save()
rows = User.query().where(User.c.email == "alice@example.com").all()
```

Tables are referenced as `project.dataset.table`. Authentication is via a
service-account key file, or whatever the ambient Application Default
Credentials provide when `credentials_path` is omitted.

### Async

`AsyncBigQueryBackend` exposes the same API. Method names are identical; add
`await`.

```python
from rhosocial.activerecord.backend.impl.bigquery.backend import AsyncBigQueryBackend
from rhosocial.activerecord.model import AsyncActiveRecord


class User(AsyncActiveRecord):
    ...


User.configure(config, AsyncBigQueryBackend)
rows = await User.query().where(User.c.email == "alice@example.com").all()
```

## Dialect

- Identifiers are quoted with **backticks**: `` `users` ``.
- Placeholders are `?`, not the driver's native `@param` form.
- Standard SQL throughout; legacy SQL is not supported.

Type adapters: `BigQueryStructAdapter`, `BigQueryArrayAdapter`,
`BigQueryJSONAdapter`, `BigQueryDecimalAdapter`, `BigQueryTimestampAdapter`.
The dialect reports `supports_struct`, `supports_array`, `supports_json` and
`supports_geography` as `True`. There is no `BIGNUMERIC` support switch —
`DecimalType` is the only numeric type — so treat the older
"BIGNUMERIC adapter" claim with suspicion.

## Local testing without a GCP account

Tests run against the [goccy/bigquery-emulator](https://github.com/goccy/go-bigquery-emulator),
so no real project is needed.

```bash
bash tests/scripts/start_emulator.sh
# or manually:
docker run -d -p 9050:9050 -p 9060:9060 \
  ghcr.io/goccy/bigquery-emulator:latest --project=test
```

Point the backend at the emulator with `api_endpoint` and
`use_anonymous_credentials`:

```python
config = BigQueryConnectionConfig(
    project="test",
    dataset="test_dataset",
    api_endpoint="http://localhost:9050",
    use_anonymous_credentials=True,
)
```

CI shards the emulator across several containers on distinct ports; see
`.github/workflows/test.yml`.

## Known Limitations

- **No `RETURNING`.** `supports_returning_insert/update/delete` are `False`;
  use a follow-up `SELECT` or `MERGE`.
- **No `IF NOT EXISTS` on views**, and no virtual generated columns,
  `ALTER COLUMN`, or `EXPLAIN` / `EXPLAIN PLAN` support.
- **No `CASCADE` / `RESTRICT` on `DROP TABLE`** and no `REFRESH MATERIALIZED
  VIEW`.
- **No connection pooling** in the backend itself.

```bash
bash tests/scripts/start_emulator.sh
export PYTHONPATH=src:tests
.venv3.14-ubuntu26.04/bin/pytest --scenarios=bigquery_emulator
```

Scenario configuration also comes from the environment:

```bash
export BIGQUERY_SCENARIOS_CONFIG_PATH=tests/config/bigquery_scenarios.yaml
export BIGQUERY_ACTIVE_SCENARIOS=bigquery_emulator
.venv3.14-ubuntu26.04/bin/pytest
```
